# 実機・外部環境での手動検証手順

この文書は、自動テスト(ConPTY を含む)では **確認できない** 項目の手順です。
ここに書かれた項目は、実際に実施して記録するまで **NOT RUN** です。
ConPTY が確定済み文字列を送るテストと、実際の IME で変換するテストは別物です。

共通の約束:

- 使い捨ての領域と合成データだけを使う。実ユーザーのデータ、実ドライブ、本物の SSH ホストに破壊的な操作をしない。
- 結果は PASS / FAIL / SKIP / NOT RUN のいずれかで記録する。実施していない項目を PASS にしない。
- 証跡: ビルドのハッシュ(`piero.exe --version` と SHA-256)、Windows のビルド番号、ターミナルの種類とバージョン、キーボード(JIS/US)、IME の名前、日時。
- 失敗時: 画面のスクリーンショット、`%LOCALAPPDATA%\piero`(使用中なら旧 `%LOCALAPPDATA%\wfile`)以下のログと受領ファイルの一覧(中身を編集・削除しない)、実行した手順の番号。
- 旧ジャーナル `%LOCALAPPDATA%\wfile\copy-journal.txt` には触れない。

## A. Windows Terminal(実端末)

前提: x64 の Windows 11、Windows Terminal(PowerShell 7 タブ)、検証対象の `piero.exe`。
個別の指定がなければ初回設定を完了し、英語UIとStandardキーボードプロファイルを使います。
転送ごとに新しい使い捨てのコピー先を用意してください。以下の状態表示は英語の目印です。
実際のビルドが表示した文字列を記録してください。

| # | 手順 | 期待結果 | 失敗時の証跡 |
|---|------|----------|--------------|
| A1 | `piero.exe --version` を実行する | `piero ` で始まる一行 | 出力全文 |
| A2 | 使い捨てフォルダで `piero.exe` を起動する | 三つのペインを表示、ステータス行が READY | スクリーンショット |
| A3 | ウィンドウを大きく/小さくする(40x12 まで) | 画面が崩れず、`Current` が見える | 各サイズの画面 |
| A4 | `j` `k` を押し続ける(キーリピート) | カーソルが連続して動き、遅れが体感されない | 動画またはキー数と画面 |
| A5 | 30 秒、何も操作しない | 画面のちらつきがない。タスクマネージャーで CPU がほぼ 0 | CPU 表示のスクリーンショット |
| A6 | 大きなファイル(約 1 GiB の合成ファイル)を `y` → 別フォルダで `p` | 進捗が表示され、`COPY done` で終わる | 画面、両ファイルの SHA-256 |
| A7 | A6 の途中で `z` を押す | `PAUSED` が出て進捗が止まる。`z` で再開 | 画面、停止中の一時ファイルのサイズ(二回) |
| A8 | A6 の途中で `z` の後に `C` | 中止を報告し、原本は変更しない。完了済みの項目と一時ファイルを項目ごとの結果と照合する | 宛先の一覧 |
| A9 | Sixel 対応端末の場合、画像ファイルにカーソルを置く | 画像が表示される。非対応なら文字の代替表示 | 画面 |
| A10 | 同期出力(DEC 2026)対応の端末で大量の再描画(スクロール) | ちらつきが少ない。非対応端末でも正常に動く | 比較動画 |

## B. 日本語 IME(Microsoft IME)

アプリが受け取れるのは **確定済みの文字列** だけです。未確定文字列(下線付きの変換候補)は端末が管理し、
アプリには届きません。アプリ側は、確定した文字を通常の文字入力として扱います。
「IME の変換確定の Enter」は端末(IME)が消費し、操作の確定とは別です。

前提: Windows Terminal、Microsoft IME(日本語)、JIS または US キーボード。使い捨てフォルダで `piero.exe` を起動する。

| # | 手順 | 期待結果 | 失敗時の証跡 |
|---|------|----------|--------------|
| B1 | `a` → `%`(新規ファイル)。IME を ON にして `こんにちは` と入力し、**変換のため Space** を押し、**Enter で確定**(最初の Enter) | この時点ではファイルは作られない。入力欄に `こんにちは` が入る | 画面。ファイルが作られたら FAIL |
| B2 | もう一度 Enter(二度目) | ファイルが作られ `Done:` と表示される | 画面、フォルダの一覧 |
| B3 | 変換中(下線が出ている間)に Esc | 変換だけが取り消される。入力欄の既存文字は消えない。ダイアログは閉じない | 画面 |
| B4 | 変換を確定してから Esc | 入力欄が閉じる(通常の Esc) | 画面 |
| B5 | 全角英数 `ＡＢＣ`、全角スペース、記号を入力 | そのまま入力欄に入る。カーソルが文字の右側にある | 画面 |
| B6 | 補助面の漢字 `𠮷`(つちよし)と絵文字 `😀` を入力 | 一文字として表示され、`Done:` のあとのファイル名も同じ | 画面、`dir` の出力 |
| B7 | 日本語の名前を入力後 Backspace | 一文字(サロゲートペアなら一つの文字)ずつ消える。文字化け(`?`)にならない | 画面 |
| B8 | ← → Home End で日本語の途中にカーソルを動かして挿入 | 文字の途中で割れない | 画面 |
| B9 | 検索(`/`)・パス入力(`g`)・名前変更(F2)・内蔵エディタ(`e`)で B1〜B8 の文字入力・変換・中止・カーソル操作を繰り返す。ファイル作成は作成画面でのみ行う | 入力内容を保持し、Unicodeの文字境界を壊さない | 各画面 |
| B10 | IME を OFF にして英数字を入力 | 通常どおり | 画面 |
| B11 | **変換中の表示位置**: `e` で内蔵エディタ(NANO プリセット)を開き、IME を ON にして `つきがきれいですね` と入力し、Space で変換して **確定せずに止める** | 未確定の文字列(下線付き)と変換候補が、編集中の行の挿入位置に出る。画面最下部のステータス行付近には出ない | 未確定中の画面全体のスクリーンショット(ウィンドウの大きさも記録) |
| B12 | B11 をウィンドウを最大化して繰り返す | 通常サイズと同じく挿入位置に出る | 最大化時のスクリーンショット |
| B13 | B11 の続きで Enter で確定する | 確定した文字列が未確定のときと同じ位置に入る | 確定後の画面 |
| B14 | 名前変更(F2)・新規ファイル名(`a` → `%`)・検索(`/`)・Go(Ctrl+L)・Vimプロファイルに切り替えてコマンド行(`:`)・設定の文字入力で B11 を繰り返す | どの入力欄でも、変換中の文字列が入力欄の挿入位置に出る | 各画面 |
| B15 | **カーソルの見え方**: B11 の編集中、ネイティブカーソルと反転表示の擬似カーソルが二重に見えないか。ファイル一覧(通常画面)ではカーソルが出ないか。`q` で終了した後、シェルのカーソルが通常どおり表示されるか | 編集中は挿入位置にカーソルが一つに見える(点滅で反転が入れ替わるのは可)。一覧ではカーソルなし。終了後は表示される | 編集中・一覧・終了後の画面(カーソル形状の設定も記録) |
| B16 | **確認の質問(IME 有効)**: NANO エディタで日本語を入力し、Ctrl+X を押す(「変更を保存しますか？ S: 保存 D: 破棄 C: キャンセル」)。IME を **ひらがな入力のまま** にする | 質問が表示され、末尾に `Enter = C` と出る(初期選択はキャンセル)。**S/D/C を打たなくても** 答えられる | 質問が出た画面 |
| B17 | B16 で ↑ を押す → `Enter = D`、↓ で `Enter = S`、さらに ↓ で `Enter = C`。Enter のみを押す | ↑↓ で選択が変わる。キャンセル選択のまま Enter ならキャンセル(編集は残り、何も保存・破棄されない) | 各選択の画面 |
| B18 | B16 で、IME を ON のまま `d` や `s` を押す(変換中の下線が出る)、全角の `ｄ` を確定する | 質問は閉じない。保存も破棄も起きない。Enter(IME の確定)を押しても、まだ質問が残るか、キャンセルになるだけ | 画面、ファイルの内容 |
| B19 | B16 で ↑ → Enter(破棄)、別の回で ↓ → Enter(保存) | 破棄ではファイルは変わらず、保存では日本語が保存される | ファイルの内容 |

ConPTY での自動確認(確定済み文字列): `PRODUCT-TUI` の `edit_jp_*` チェックと `tests/test_term_input.c`。
これらは IME の変換を試験していません。

## C. インストール・PATH・署名・SmartScreen

[パッケージ作成](packaging.md)に従い、Inno Setupで`piero-Setup-x64.exe`を作成します。ビルドとインストール・削除の結果は別々に記録してください。
ZIP 候補と PATH 補助ツールの確認はできます。インストール/アンインストールは、
スナップショット付きの使い捨て VM で実施します。

| # | 手順 | 期待結果 | 失敗時の証跡 |
|---|------|----------|--------------|
| C1 | `python tools/check_package.py <payload> --executable piero.exe --installer-helper` | PASS(在庫とハッシュが一致) | 出力全文 |
| C2 | ZIP を新しい空のフォルダに展開して `piero.exe --version` | 起動し、横に `LICENSE`、`LICENSES\`、`languages\` がある | 展開先の一覧 |
| C3 | (VM)インストーラーを実行。PATH のチェックは既定でオフ | `%LOCALAPPDATA%\Programs` 以下に入る。管理者権限の確認が出ない | インストール先、昇格ダイアログの有無 |
| C4 | (VM)C3をアンインストールしてからPATHを選択してインストールし、新しい端末で `piero --version` | 動く。PATH に重複がない。レジストリ値の型が保たれる | `reg query HKCU\Environment /v Path` の前後 |
| C5 | (VM)別プログラムが PATH を変えたあとにアンインストール | PATH を触らず、手動確認を求める | PATH の値、画面 |
| C6 | (VM)アンインストール | `%APPDATA%\piero`、`%LOCALAPPDATA%\piero`、`%APPDATA%\wfile`、`%LOCALAPPDATA%\wfile`の個人データを再帰削除しない | フォルダーの一覧 |
| C7 | 署名の確認: `signtool verify /pa /v piero.exe` | 署名キー未設定のため、現状は「署名なし」。署名後は検証 OK | 出力全文 |
| C8 | SmartScreen: ZIP をブラウザでダウンロードして展開して実行(Mark-of-the-Web 付き) | 警告が出る場合がある。保護を無効にして通さない。結果を記録 | 警告画面 |

## D. SSH/SFTP(読み取り専用の閲覧)

対応する操作は[機能](features.md)を参照してください。閲覧と読み取りはできますが、書き込みはありません。ご自分の `ssh.exe` と、ご自分の ssh 設定にあるホスト名を使います。piero は鍵も設定も読まず、ホスト鍵を受け入れることもしません。SSHが対話なしで使える認証を用意してください。パスワードや対話式認証の入力はできません。
自分が管理し、試験を許可されたサーバーでのみ行ってください。実施するまでは **NOT RUN** です。

| # | 手順 | 期待結果 | 失敗時の証跡 |
|---|------|----------|--------------|
| D1 | 端末で `ssh <host>` を一度実行し、ご自分でホスト鍵を受け入れる | 鍵が `known_hosts` に入る | 端末 |
| D2 | piero で `g` → `sftp:<host>/home` と入力して Enter | フォルダーが一覧され、ステータス行に `SFTP (read-only)` と出る | 画面 |
| D3 | まだ鍵が未登録のホストで D2 を行う | ホスト鍵が未登録と表示し、SFTPセッションは開始せず、鍵も受け入れない | 画面 |
| D4 | そこで `a`、`R`、Delete、`y`、`x`、`p`、`o` を押す | すべて「SFTPの場所は読み取り専用です」で拒否される | 画面 |
| D5 | 小さなテキストファイルを選んで `e` を押す | 読み取り専用で開く。Ctrl+S は拒否される。Windows のフォルダーへの「名前を付けて保存」はできる | 画面 |
| D6 | 一覧の取得中にサーバーを止め、`r` で再読み込みする | 時間制限の後に理由が表示される(固まらない)。次の試行は新しい接続を 1 回だけ作る | 画面 |

## E. WSL

E1〜E2 は読み取り専用の調査用プローブ `probe_wsl`を使い、E3 以降は製品を使います。必ず、そのために作ったフォルダー(例: `/tmp` の下)だけで行い、実データでは行わないでください。

| # | 手順 | 期待結果 | 失敗時の証跡 |
|---|------|----------|--------------|
| E1 | 停止中のディストリビューションがある状態で `probe_wsl` を実行 | ディストリビューションの起動を含む最初の一覧取得の所要時間を記録する。終了後の `wsl --terminate <name>` は専用のテスト用ディストリビューションだけに行う | 出力全文 |
| E2 | 結果の確認 | このパスでは FileId・大文字小文字情報が使えないため、製品は識別情報に頼るエンジンの代わりに WSL 専用の操作を使う | 出力全文 |
| E3 | Windows Terminal で `g` → `wsl:` と入力して Enter | 「wsl:<ディストリビューション名> と入力(登録済み: …)」と表示され、どれも起動しない | 画面と、前後の `wsl -l --running` |
| E4 | `g` → `wsl:<distribution>`(起動中のもの)→ Enter | ルートが一覧表示され、ステータス行に `WSL` と出る | 画面 |
| E5 | 自分で用意した作業用フォルダー(例 `/tmp/try`)で `a`(作成メニュー)と `F2`/`R`(名前変更)を押す | ファイルとフォルダーを作成・名前変更できる。既にある名前は拒否され、上書きされない。`o`(他のアプリで開く)は拒否される | 画面 |
| E6 | ディストリビューション内に `File` と `file` を作り(ext4)、一覧を表示 | 両方表示され、選択後に入り直しても正しい方に戻る | 画面 |
| E7 | シンボリックリンクがある一覧 | リンクとして表示され、Enter で辿らない | 画面 |
| E8 | 別の使い捨てフォルダーで、空いている名前に `y` → `p` でコピーし、同名がある場合も試す。続けて `x` → サブフォルダーで `p`、`x` → Windows のフォルダーでも `p` を試す | 空き名にはコピーし、既存名は拒否する。移動はディストリビューション内で動き、Windows 側へは拒否する | 画面とコピー元・先のハッシュ |
| E9 | ファイルと中身のあるフォルダーを選んで Delete を押す | 完全に削除するかの確認に件数が出る。`n` か Esc では何も消えず、`y` で項目とフォルダーの中身が消える | 画面 |
| E10 | スクリプトを `e` で開いて 1 行変え、Ctrl+S で保存 | Linux の権限(`ls -l`)が変わらない。変更前の内容は `<name>~` に残る。開いてから保存までの間に Linux 側で変更されていれば保存は拒否される | `ls -l` と画面 |
