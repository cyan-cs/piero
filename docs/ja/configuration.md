# 設定

## 設定ファイルと編集

既定は`%APPDATA%\piero\config.ini`です(古い`%APPDATA%\wfile\config.ini`だけがある場合はそちら)。`--config <path>`には既存の有効なファイルが
必要です。INIは厳密なUTF-8で、BOMはあってもなくても構いません。行末のコメント、引用符、エスケープはありません。
設定画面で編集しても、未知のキーとコメントは残ります。ほかで変更されたあとに保存しようとすると拒否し、
設定画面の`r`で読み直せます。言語、テーマ、色は、変更するとすぐに反映して見せます。
「次回起動」と書かれた項目は、再起動が必要です。
不正なスキーマのファイルを、バージョンのない書き込み可能なファイルに変えることはなく、将来のスキーマは読み取り専用です。
同じ意味のセクション名の別名は、保存するときに正規化します。
設定を保存すると、元のファイルを`config.ini~`、または`config.ini~2`から`config.ini~9`の最初の空き名に残します。9個すべてが使われていると保存を拒否します。

## よく使う項目

```ini
[meta]
schema_version = 1

[general]
language = auto

[keyboard]
profile = standard

[appearance]
theme = spade
color_mode = auto

[preview]
images = true
graphics = auto
image_quality = high
image_style = default
directory_preview = true
image_cache_mib = 32
text_max_kib = 256
text_fallback_encoding = cp932

[updates]
enabled = false
consent_recorded = false

[copy]
verify = sha256

[editor]
enabled = true
keymap = piero
backup = true
max_size_mib = 32
undo_mib = 16
```

`language`は`auto`、同梱の`en`・`ja`に加え、[翻訳](translating.md)で説明する追加言語のコードを受け付けます。
autoはWindowsの優先UI言語の一覧から利用できる言語を選び、一致しなければ英語を使います。
CLIの起動時の診断とヘルプは、常に英語です。
`text_fallback_encoding`は`cp932`などの`cp<number>`形式、`utf8`、`utf-8`を受け付けます。
数字だけの指定は無効で、警告を出して既定値を使います。
`profile`は`standard|nano|vim|custom`です。`[editor] keymap`は`piero|nano`だけを受け付けます。
Vimでの編集は、この古い設定ではなく、キーボードプロファイルで選びます。
`theme`は`spade|heart|diamond|club|joker|king|queen|ace|custom`、
`color_mode`は`auto|truecolor|256|16|none`です。autoのときは、`NO_COLOR`や`TERM=dumb`があると色を使いません。
カスタムテーマは、`[theme.custom.<id>]`、`name`、`base`、`#RRGGBB`形式の色で定義します。
設定画面で、複製、編集、名前の変更、削除ができます。インポートとエクスポートはありません。

## 表示と一覧の項目

`[terminal] ambiguous_width=1|2`(既定は`1`)は、端末が「East Asian Ambiguous(曖昧幅)」の文字を何セルで描くかを指定します。
対象は、アクセント付きのラテン文字、ギリシャ文字、キリル文字、矢印、丸などの記号、私用領域のアイコン文字です。
端末側でこれらを全角幅で描く設定にしている場合だけ`2`にしてください。
piero はそれらを 2 セルとして数え、桁、カーソル、長い名前の省略を、端末の描画に合わせます。
UI言語から推測せず、端末の設定に合わせてください。既定は1セルです。
結合文字は常に幅0、CJKの文字は常に2セルのままです。
枠線とキー案内はASCIIだけを使うので、この設定の影響を受けません。設定は、pieroの起動時に一度だけ読みます。

`[files] directories_first=true|false`(既定は`true`)は、フォルダーをファイルより先に並べます。
`false`にすると、フォルダーとファイルを区別せず、並べ替えのキー(名前・サイズ・日付・拡張子)で一緒に並べます。
`S`で並べ替えを変えた後も同じです。

`[git] folder_color=true|false`(既定は`true`)は、Gitのリポジトリ内で、変更されたファイルを含むフォルダーに色を付けます。
ファイル名は、常にGitの文字と同じ色になります。設定 > ファイルからも変更できます。

## プレビューと安全に関わる項目

### 画像と描画

`images=true`(既定)では、プレビューに画像とPDFのページを表示します。デコードは隔離されたホストだけで行います。`images=false`にすると次回の起動からオフになり、プレビューにその旨が表示されます。

入力上限は128 MiB、元画像の上限は256,000,000画素です。デコード中に縮小する場合があり、処理の成否はコーデックとホストのメモリ(512 MiB)・時間(12秒)の上限にも左右されます。構造検査は一部の破損を検出しますが、すべての破損を検出するものではありません。

`graphics=auto|sixel|text`です。autoは端末のSixel・消去機能の応答、ピクセル寸法、パレット情報を確認します。
Sixelの明示指定は対応機能の応答を必須にしませんが、取得したピクセル寸法は必要です。
対応すると分かっている端末でのみ使ってください。非対応端末では表示が崩れる可能性があります。
textではSixelを使いません。

`image_quality=high|balanced|fast`、`image_style=default|halfblock|ascii|off`です。

### コピーの検証とバックアップ

`verify=none|sha256|hmac-sha256`で、既定は`sha256`です。`none`はコピーの検証を無効にしますが、
別ボリュームへの移動では読み戻し検証を必ず行います。

Windowsのローカルフォルダーで完全削除を許す設定はありません(WSLの削除は完全削除です)。既存の名前の上書きは、設定ではなく、ジョブごとの確認で選びます。

原本を残す方針なので、`backup=false`は受け付けません。

### 下書きとMarkdownの編集

`[editor] recovery_draft=true|false`(既定は`true`)は、編集中の未保存テキストを数秒ごとに`%LOCALAPPDATA%\piero\drafts`(使用中なら`wfile`)の下書きへ書き出し、次に同じファイルを開いたときに復元を尋ねます。秘密を思わせる名前、ネットワーク上のファイル、`.ssh`・`.gnupg`・`.aws`フォルダー内のファイル、
UTF-8の下書き本文が2 MiBを超える場合は対象外です。サイズの判定は、元の文字コードでのファイルサイズとは異なります。`false`にすると、保存するまで何も書き出しません。
下書きは元のファイルとは別の場所に平文で保存され、暗号化されません。
ファイル名による除外は推測に基づくもので、本文に秘密情報が含まれるかは検査しません。

`[editor] markdown_split=auto|on|off`(既定は`auto`)は、Markdownのファイルを2ペイン(左が編集、右がプレビュー)で編集するかを決めます。`auto`は100桁以上、`on`は60桁以上で表示し、`off`は表示しません。`Alt+M`でそのセッションの間だけ変えられます。設定画面にはありません。

### 外部起動と自動読み取り

`[launch] working_directory=neutral|file_dir`の既定は`neutral`です。
リモートやクラウド上のファイルの自動読み取りは、設定で求めても無効のままです。

使えるキーと値の範囲は`src/config/wf_config.c`に、Customのコマンド名と全一覧の生成方法は[キー操作](keybindings.md)に、
原本の保持と競合についての制限は[安全性](safety.md)にあります。
現在のスキーマと、上の既定値を使ってください。

### 更新確認

`[updates] enabled`は、`consent_recorded=true`を保存したあとで、リリース情報の自動確認を
許可します。既定はどちらもfalseです。設定が不正なときは、自動確認は無効です。
設定 > 更新では、自動確認が無効でも、手動で確認できます。更新ファイルのダウンロードや
インストールは行いません。[更新](updates.md)を参照してください。

## タブと場所

タブは実行中だけ保持し、保存しません。よく使う場所は設定ファイルに保存できます。
`m`のあとに文字キーを押すと現在のフォルダーを保存し、`'`のあとに同じ文字を押すと移動します。
保存には設定と同じ手順を使い、古い版では未知のセクションとして保持されます。

```ini
[places]
a = C:\Work
b = D:\Photos\Archive
```

キーは小文字の英字、値はフォルダーのパスをUTF-8で指定します。同じキーを重ねた場合は最初の値を使います。
値が空、制御文字を含む、長すぎる場合は警告して無視します。
アーカイブ内やSFTPのフォルダーは保存できません。将来のスキーマの設定ファイルにも書き込みません。

## 前回の続きから始める

`piero --continue` は、前回の実行が保存した状態(フォルダー、カーソル、スクロール、選択した名前、プレビュー)を元に戻します。
保存は、オンにするまで行いません。`[session] persist=true` か、設定 > 全般で有効にします(変更は次回の起動から有効です)。
オンの間は、状態が変わって 1 秒後に、キー操作が待つことのない専用のスレッドで書き出し、終了時にもう一度書き出します。
保存するのはパスと名前だけで、ファイルの本文は含みません。

- フォルダー指定または`--setup`と、`--continue`は併用できません。競合する起動指定は拒否します。
- 保存がない、保存データが壊れている、形式に対応していない場合は、その旨を表示して通常どおり起動します。
  壊れたデータや未対応バージョンのデータがあれば、セッションの書き込みを拒否します。
  `--continue`なしで保存だけを有効にした場合や、ヘッダーを読み取れない場合も同じです。
  ファイルを保管したうえで`piero --forget-session`を使うと、内容を空にして保存を再開できます。
  [対処方法](troubleshooting.md#セッションデータが壊れている場合)を参照してください。
- 保存したフォルダーがなければ、その上にある、存在する最も近いフォルダーを表示します。ネットワーク共有は、いつもどおり確認します。
- 書き込むのは同時に 1 つの piero だけ(`session.lock` を持つもの)です。ほかの piero は読むだけで、保存しないことを表示します。ロックは、その piero がどのように終了しても、システムが解放します。
- ファイルは、piero が使っている状態フォルダー(`piero`、旧フォルダーを使う環境では `wfile`)の `session.a`、`session.b`、`session.lock` です。`piero --forget-session` で保存内容を空にします。内容は消え、ファイルは残ります。
- エディタが画面を占めていた場合、`--continue`は保存したフォルダー内の同じファイルをもう一度エディタで開き、カーソルと表示位置を元に戻します。
  本文はセッションに含みません。未保存の本文はエディタの下書きで、いつもどおり、エディタが復元するか破棄するかを尋ねます。
  戻すのは現在のファイルだけで、Vim のモードは戻しません。その間に変更されたファイルは今の内容を読み、保存時の競合の検査もそのままです。
- 異常終了後に復元できるのは、最後に書き込みが成功した時点の状態です。1秒という間隔は保存処理を開始する目安であり、失われる変更量の上限を保証しません。未保存の本文は、下書きの書き込みが成功していた場合だけ復元できます。
- 状態を戻す操作は利用者のファイルに書き込まず、確認にも自動で答えません。操作の復旧は別の仕組みです。
  アーカイブはそれを含むフォルダーから再開し、SFTPの場所は保存しません。選択した名前は最大256件を保持します。
