# コーディング規約

規約の本体は、MUST / SHOULD / MAYを区別した[CODING_RULES.md](../CODING_RULES.md)(英語)にあります。このページは短い要約で、規約を追加するものではありません。

## 言語・整形・命名

ISO C17としてビルドし、C++は使いません。プラットフォームのABI注釈と、コンパイラ固有の
診断用の組み込み処理は、既存のものを隔離して使い、通常の実装のコードはC17で書きます。WindowsのUTF-16とABIの
前提を明示し、不変条件、所有権、制御の流れを明確で単純に保ち、
数行を隠すだけの抽象化は足しません。整形の原本は`.clang-format`です。
LLVMベース、80桁、字下げはタブで幅8、独自の波括弧、includeの順序は保持、という設定です。
関数名は`wf_`、型名は`Wf`、定数名は`WF_`で始めます。ローカルの名前は、周囲のコードに合わせます。

## 所有権とメモリの安全性

ポインターが、借りたもの、コピーしたもの、所有するもの、譲り渡すもののどれかを、はっきりさせます。配列とキューには上限を設け、
容量と、初期化済みの要素数を区別します。確保や変換の前に、オーバーフローを確認します。
途中までしか初期化できなかった失敗も含めて、各リソースを1回だけ解放します。停止がタイムアウトしたあとに、生きている
ワーカーのメモリを解放してはいけません。状態の重複と、不要な確保は避けます。
キャッシュは観測した結果であって、許可ではありません。バイト、UTF-16の単位、表示セル、ピクセルは区別します。

## Win32とエラー

パスにはwide APIを使います。依存するSDKのヘッダーより先に、`windows.h`をincludeします。
呼び出しが失敗したら、後片付けの前に`GetLastError`やHRESULTを取っておきます。
失敗の意味、一部だけ成功したことの記録、公開した結果が不確かな状態は、そのまま残します。
ハンドルの所有権、同一性、ADS、リパースポイントの確認を、パスからの推測で置き換えてはいけません。
所有権をはっきりさせたいときは、後片付けの経路を一つにまとめ、巨大な汎用ヘルパーにはしないでください。

## コメント・性能・テスト

理由、所有権、不変条件、APIの契約は、英語のコメントで書きます。見ればわかるコードを、そのまま説明するコメントは避け、
既存の、局所的な`//`と、契約の`/* */`の使い分けに従います。アルゴリズムを変える前に計測し、
不要なI/Oや、イベントループでのポーリングは避けます。ベンチマークのために整合性の確認を削ってはいけません。
安全性に関わる変更には、意味のある回帰テストと故障のテストを使い、自分のものと証明できる、捨ててよいデータで試します。
関連するテストから全体の回帰へ進み、環境が原因のFAIL/SKIP/NOT RUNは、正確に記録してください。
