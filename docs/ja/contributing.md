# 貢献

## 貢献の前に

この製品は、既知の制限がある開発プレビューです。本体のコードと貢献にはMITを適用します。
提供する権利のあるものだけを提出し、第三者の表記は残してください。[ライセンス](licensing.md)と
[セキュリティ](security.md)を読んでください。公開の場には、機密性のある脆弱性の情報や、個人のテスト用ファイルを
投稿しないでください。

## 開発の手順

[開発](development.md)に従って、x64 Visual StudioのC++ツールとWindows SDK、clang-clまたはMSVC、
CMake、Ninjaを用意します。両方のコンパイラを、別のディレクトリでビルドしてテストします。
`.clang-format`を使い、Cのファイルとヘッダーの変更した行を整形します。
`clang-format --dry-run --Werror <explicit paths>`は、指定した各ファイルの全体を検査します。
第三者のコードの整形は保持してください。
[コーディング規約](coding-style.md)に従い、ISO C17と文書化された安全性の不変条件を守ってください。

## Pull Requestとコミット

具体的な問題、変更後の動作、テスト、残る制約を書いてください。コミットは目的ごとに分け、
メッセージは英語で書きます。安全性に関わる変更には、範囲を絞った回帰テストを足し、モック、Win32、ConPTY、
実際の端末のどれで確かめたかを区別してください。故障注入やミューテーションのテストで「検出した」と数えられるのは、
アサーションの失敗が最後まで報告されたときだけです。テスト基盤のエラーは数えません。
利用者が編集中のファイルのうち、今回の変更と関係ないものは、そのまま残してください。
`.mcp.json`、認証情報、生成されたEXEやDLL、生のログ、個人の文書はステージしないでください。手元での作業には、pushや公開は含まれません。日英のガイドとi18nの表は同時に更新してください。

## AIを使った貢献

AIを使った貢献も受け付けています。提出する変更の責任は貢献者が負います。
Pull Requestを作る前に、すべての変更を読んで理解し、ビルドとテスト、安全性・セキュリティの確認、
コーディング規約と設計方針への照合を行ってください。既知の不具合は提出前に修正し、
テストできていない動作や残るリスクはPull Requestに記載してください。

AIツールは、人によるレビューや責任の代わりにはなりません。
確認やテストが不十分な貢献は、メンテナーが受け付けない場合があります。

## 安全性のレビュー

削除、置換、同一性、ADS、復旧、ワーカーの寿命、AppContainerを変えるときは、不変条件と失敗したときの経路を
示す証拠が必要です。速度やテストの件数のために確認を弱めないでください。迷ったときは、原本を残します。
自分のものだと証明できる、捨てても構わないデータを使ってください。電源断のテストには、所有者を確認した、
捨ててよいVMかディスクが必要です。ホストのドライブや本物のデータは使えません。

## スクリーンショット

### メンテナーが用意するファイル

現在のREADMEにはスクリーンショットを掲載していません。
`assets/screenshots/`に`main.png`、`image-preview.png`、`pdf-preview.png`、
`editor.png`、`settings.png`を置きます。
メイン画面は16:9の1920×1080か1600×900くらい、詳細画面は内容に合う大きさにしてください。
GitHubのライト・ダーク両テーマで見やすいか確認してください。

### 追加と確認

捨ててよいデータで本物のアプリを撮影し、個人アカウント、ユーザーパス、非公開ファイル名、
文書内容、トークン、認証情報が画面に入らないようにします。画像はメタデータも確認し、
切り取りや伏せ字の処理をしてからステージします。画像は紹介用であり、安全性テストに合格した証明ではありません。
`main.png`を追加したら、ルートのREADMEの紹介文の直下と、日本語READMEの対応する場所に書き足します。

```markdown
![piero showing Miller columns](assets/screenshots/main.png)
```

日本語READMEでは`../../assets/screenshots/main.png`と日本語の代替テキストを使います。
`python tools/sync_readme.py`と`python tools/check_docs.py`を実行してください。
ファイルができるまでは、例はこの手順の中にとどめ、READMEに壊れた画像参照を足さないでください。
