# トラブルシューティング

画像・PDFプレビューを起動できない場合は、AppContainerを有効のままテキスト表示を
使ってください。プロファイル作成の失敗、隔離プロセスの起動失敗、ファイルのデコード失敗は区別して調べます。
エラーを隠すために、管理者として実行したり、広い範囲にACLを付与したり、隔離を外したりしないでください。
開発者は通常のユーザーセッションと診断プローブを比較できます。

置換保存には`name~`から`name~9`までの最初の空き名を使います。9個すべてが使われている場合は、バックアップを安全な場所へ移すか、Save Asを使ってください。復旧通知が出たときは、残されたファイルを確認してください。記録を削除しても、中断した
操作は元に戻りません。[制限事項](safety.md)を参照してください。

Sixelの交渉に失敗したら文字表示を使ってください。クラッシュ後はリサイズ・再起動で
端末を復元できる場合があります。端末リセットは導入ガイドを参照してください。
表示の報告には端末バージョン、フォント、DPI、最小の操作列を含めてください。

更新確認が利用できない原因にはオフライン、レート制限、非公開リポジトリ、公開済み
リリースがない場合があります。起動は継続します。ダウンロードとインストールは手動です。
[更新](updates.md)を参照してください。

## 「開く」が使えない、または起動時にコピーが拒否される

pieroは、状態フォルダー(`%LOCALAPPDATA%\piero`、または古い`wfile`)の中に、非公開の作業フォルダー(`cwd`)と
ログを置きます。このフォルダーは自分のアカウントが所有し、継承された権限がなく、リンクでないことが必要です。
これを確認できないときは、**「開く」とログが無効**になり、ファイルでEnterを押すと
「開けません: 非公開の状態フォルダーを確認できません」と表示されます。画面を開く前に出力される行が原因を示します。

| 出力される原因 | 意味 |
|---|---|
| not private to your account (owner or permissions) | インストーラー、バックアップからの復元、管理者権限のプログラム、コピーなど、ほかのものがフォルダーを作り、継承された権限や別の所有者になっている |
| its working folder is not empty | `cwd`にファイルが残っている。pieroは削除しません |
| it is a link / not a folder | フォルダーの場所にジャンクション、シンボリックリンク、またはファイルがある |
| access to it is denied | あなたのアカウントでは開けない |

pieroは、検査を通すためにフォルダーの権限や内容を変更しません。診断と既存の状態を保管し、
診断が示すフォルダーの所有者、権限、内容を確認してください。復旧警告を回避するために状態フォルダー全体を
改名・置換すると、未解決の記録が見えなくなるおそれがあります。
検査に失敗したフォルダーを特定できない場合は、変更する前に不具合を報告してください。
pieroが正常に作成したフォルダーには非公開の権限を設定します。

コピーは、それぞれの理由で拒否されます。「記録用フォルダーを使えません」(状態フォルダーがリンクやファイル、または
見つからない)、「コピー記録を書き込めません」(フォルダーや記録ファイルへのアクセスが拒否された)、「未確認の履歴」
(設定 → 情報を参照)です。どの場合も何もコピーされず、ファイルは変更されません。

## ファイルの使用状況の照会やプロセス操作が使えない

Restart Manager は、プログラムを一覧にする前に失敗することがあります。
照会の不具合を報告するときは、表示された Windows のエラーコードも残してください。
一覧が空でも、ファイルが使用されていないとは限りません。「閉じる」「終了する」には、
プロセスの識別情報と親プロセスの関係を確認できることも必要です。
プロセス一覧が不完全な場合や親子関係を確認できない場合は、一覧に表示された
プログラムでも操作を拒否します。

## セッションデータが壊れている場合

セッション破損の警告は、保存した移動先などの状態を復元できなかったことを示します。
ファイル操作の復旧記録や、エディターの下書きとは別です。
破損、読み取り不能、未対応形式と判定したデータは、後続のセッション保存で置き換えません。
`--continue`なしで保存だけを有効にした場合も同じです。
`session.a`と`session.b`を保管し、警告の内容を添えて不具合を報告してください。
その保存状態が不要なら、`piero --forget-session`で両ファイルを空にして、新しい保存を始められます。
消去に失敗した場合は、保存の禁止状態を維持します。
セッションの警告に対処するために、ファイル操作の復旧記録を消さないでください。
