# アーキテクチャ

## 構成の境界

pieroは、WindowsのUTF-16とABIを前提にしたISO C17の製品で、ほかの環境に移せるライブラリではありません。
Win32に渡す名前はUTF-16、表示には端末制御文字を無害化したUTF-8を使います。
`src/main.c`はサービスを起動し、`src/main_pump.c`は入力、ワーカーのイベント、
ディレクトリ通知、処理期限を調整します。`src/ui/`のアプリケーションモジュールがビューの状態と世代を持ち、
`src/render/wf_present.c`が文字セルの差分を出力します。
Sixelには、独立したグラフィックス層と、消去と表示についての明示的な規則があります。

## 所有権と並行処理

ディレクトリのスナップショットは、配列、生の名前、表示用のバッファを所有します。ビューは、カーソル、
絞り込み、スクロールを所有します。要求は借りた文字列をコピーして持ち、結果はpollで所有権を受け渡します。
ディレクトリ、テキスト、画像、事前確認の観測結果は、あとから来たもので置き換えられ、古い世代の結果は拒否します。
受け付けたファイル操作の完了記録は、通知なしに置き換えてはいけません。
Navigation Memoryは位置のヒントにすぎず、ファイル操作を許可する根拠とは無関係です。
先読みする範囲は有限で、失敗した推測の要求を無限に再試行することはありません。

ディレクトリの通知は、現在の一覧、選択中の子項目、無関係な子孫の変更を区別します。
通知の欠落や不正な形式があれば、安全側に倒して再取得します。再検証中に保持するプレビューは、
識別情報とメタデータを確認したうえで「以前の読み取り専用表示」として示し、ファイル操作の許可には使いません。
これにより、無関係な変更で同じプレビューを破棄・再読込することを避けます。
回帰テストは`tests/test_preview_stability.c`と`tests/test_watch_notifications.c`にあります。

`stop`は、タイムアウトしたときにも所有権を引き取ります。停止が遅れているワーカーは、I/Oから戻るまで
自分のバッファを保持し、契約どおりに完了ハンドルを渡します。呼び出し側はそれを閉じ、完了するまで
借りているコンテキストを生かしておきます。UIの破棄で要求をキャンセルすることがあるため、
その終了までは、サービスのポートを使える状態にしておきます。
戻ってこないOSのI/Oは、生きているワーカーのメモリを解放しても解決しません。

## ストレージと隔離

`fs/`は、検査付きのファイル操作と所有権の証明、`xfer/`は、方針、コピーと検証、記録、ワーカー、
`edit/`は、テキストと、検査付きの置換保存を扱います。`recovery/`は、所有権を証明できるローカルの記録を扱い、
コピーエンジンが手動で確認するための一覧とは別のものです。
`preview/`は、テキストと画像の入力を制限し、WIC/Windows.Data.PdfをAppContainerの中で動かします。
`archive/`は、静的リンクした読み取り専用のlibarchiveとデコンプレッサーを使います。
`config/`、`input/`、`i18n/`は、設定、安定したコマンドとキーマップ、翻訳を保持します。

## 移動と表示の上限

Navigation Memoryは128フォルダーの位置を保持します。一覧は最大500000項目、
フォルダーのプレビューは最大2000項目です。先読みは前方5・後方3フォルダーを8 MiB以内で読み、
リンクをたどりません。これらは資源使用量の上限であり、すべてのファイルシステムでの応答速度の保証ではありません。
